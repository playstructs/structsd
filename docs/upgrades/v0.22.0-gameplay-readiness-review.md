Reviewed 2026-09-16 against the current worktree. This covers the power decisions
in all 20 `msg_server_{struct,fleet,planet}_*.go` handlers and their shared
readiness methods. It does not complete the separate permission, passive-defense,
raid-clock, root-eligibility or combined block-cost reviews.

## New handler matrix

`app/gameplay_readiness_supply_test.go` exercises sixteen actions in four native
staking states: healthy, sole-source jail, jail with an independently bonded
backup, and jail/unjail before deferred repair. Its 64 cases use the shipped
Stealth Bomber, Ore Extractor, Ore Refinery and Field Generator types, real
delegations, the v0.22 efficiency gate, and real message-server methods.

The fixture establishes unchanged raw capacity after jail and checks the live
owner result independently before invoking the action. Powered refusals preserve
all captured Structs, bank and auth rows and permit only caller-activity events.
Every successful case asserts its gameplay result. Mining, refining and build
completion use valid proofs against unchanged production difficulty, with enough
elapsed blocks to make the work inexpensive. These are handler tests with real
staking, not signed ante or native-daemon lifecycle tests.

The test complements existing source-loss controls for secondary allocations,
player/reactor admission, movement, planetary cannon/jamming, and generators. It
does not replace those independent graph, signed-transaction or lifecycle tests.
Evidence: `/tmp/structs-gameplay-readiness-focused.log` and
`/tmp/structs-gameplay-readiness-complement.log`.

## Passive behavior and remaining scope

Counter-attacks and registered defenders run their readiness checks when used.
Planetary cannons and jamming consult live owner supply after the earlier fixes.
Unit evasion, armor, targeting-blocking capability and the target's stored hidden
flag remain separate targeting/damage rules. This review does not silently make
those rules require an online target: current targeting explicitly permits
attacks against built offline targets. The broader passive-effect decision audit
remains open.

Raid vulnerability continues to follow the explicit Command Ship/fleet state
transition. Raid proof difficulty still reads the stored planetary shield
contribution. Relating either to an earlier owner power-loss height is the
pending timing policy; no clock or shield behavior changes are made here.

The new matrix establishes action-level integration for the stated native source
loss cases. It does not establish all root eligibility, large/deep graph cost,
concurrent settlement/redelegation safety, every secondary-key permission, or
final native upgrade acceptance. Those remain in the main plan's release gates.

## Allocation ancestry identity review

The live ancestry check previously treated consistent grid counters as sufficient
for some nodes without resolving their records. A missing player, guild or
intermediate substation could therefore pass; so could a missing reactor before
efficiency activation, or an unsupported object kind. These are stale/malformed
state regression cases, not evidence that an ordinary transaction can create
those records. Direct struct sources were already refused.

`CheckSubstationSupply` now resolves every visited node through its existing
`CurrentContext` cache. Missing records and cached deletion flags refuse supply;
unsupported source kinds also refuse. A record whose identity differs from its
cache key returns `SupplyCheckIncomplete`, preserving the distinction between
inconsistent evidence and a known shortage. Cached creation remains visible, and
each invocation rechecks changes made after a previous successful check. No
parallel context, keeper scan or new persistent index is introduced.

The historical interpreter already requires node existence and rejects mismatched
record identities. This change repairs the live check; it does not change sealed
history, settlements, events or stored capacity. Owner infusion backing, reactor
eligibility and generator lifecycle checks still run under their existing rules.
It does not establish that every unit of raw owner capacity has a backing row.

`allocation_supply_identity_test.go` reproduces the old acceptance for eight
missing/unsupported roots, retains the direct-struct refusal control, and checks
uncommitted identities, tombstones and replacement identities for the four
supported node kinds. A missing intermediate station has valid incoming rows and
matching counters, so rejection cannot accidentally depend on an unrelated
inventory mismatch. The tests also check zero available headroom and refusal to
create a downstream allocation without consuming an allocation ID. The missing
node cases run before and after activating the economy flag.

The focused supply suite passes in 25.837 seconds. Its existing shared-budget
controls measure **6,171,931 gas** for a complete 1,023-link chain and
**6,174,777 gas** when the 2,048-unit budget is exhausted. Expanding the unvisited
graph to 10,000 links leaves the exhausted cost unchanged. These are isolated
keeper measurements, not a bound on whole-transaction or combined block cost.
The failing-before and passing logs are `/tmp/structs-supply-identity-before.log`
and `/tmp/structs-supply-identity-focused.log`.
