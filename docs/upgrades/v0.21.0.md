# v0.21.0 upgrade notes

The v0.21.0 release combines guild-bank and charter features with consensus,
authorization, staking, agreement, and state-repair work. This document is the
operator-facing index; the handler and its tests remain the source of truth.

## Binary behavior changes

### Guild bank

- `MsgGuildBankConvert` converts alpha to an existing guild token at its current
  collateral ratio. Convert-in fees remain in collateral, and a nonzero minimum
  output protects callers from ratio movement.
- `MsgGuildBankConvertToken` composes a source redemption with a target
  conversion and applies both guilds' configured fees.
- Redemption uses integer `floor(amount * collateral / supply)` arithmetic so
  rounding always favors the collateral pool.
- Native guild tokens may be delivered only to registered players, the structs
  module account, and indexed provider pools. Existing IBC v1 escrow balances
  are protected so confiscation cannot burn voucher backing.
- Provider collateral is confiscatable only above the amount owed to open
  agreements. Swept earnings remain confiscatable.

### Guild policy and charters

- Guild join-policy enum values are validated on write and denied by default on
  read. Unknown proto3 enum values can no longer fall through authorization
  switches.
- Membership approval and acceptance require an existing pending application.
  Creation paths retain a separate get-or-create loader.
- Guild creation is priced by a chain-global proof-of-work charter, with a
  one-time entitlement for eligible bonded reactors.
- Third-party founding uses an offline founder consent bound to founder,
  reactor, entry substation, endpoint, and charter anchor. It is accepted only
  on the proof path, whose anchor movement makes the consent single-use.
- Guild ownership and membership are independent. Guild-addressed administrative
  messages accept an explicit guild id while preserving membership fallback for
  existing clients.

### Staking, reactors, and infusions

- Reactor energy follows validator health. Jailed or missing validators produce
  zero energy without moving stake or erasing fuel.
- `MsgReactorRestart` reconciles a reactor from live staking state when normal
  rebond hooks cannot restore it.
- `BeforeDelegationRemoved` explicitly clears source fuel because it fires
  before staking deletes the delegation and therefore cannot reconcile safely.
- Infusion ownership follows the current owner of its address.
- Address sweeps now assemble a real delegation transfer: settle distribution,
  merge destination shares, initialize destination reward state, and reconcile
  both infusions.
- In-flight redelegations and unbonding delegations cannot be rekeyed through
  public SDK APIs. Strict address moves refuse them; address revocation leaves
  the stake in place and removes its game capacity so a compromised key cannot
  block eviction.

### Agreements and providers

- Primary-address collateral debits require the signing key's token-transfer
  permission.
- Agreement service starts at the same block as the provider checkpoint clock.
- Teardown checkpoints before changing provider load, settles consumer
  collateral before provider revenue, and claims settlement exactly once.
- Missing allocations no longer abort the one opportunity an expiry has to
  remove its agreement and load.
- Capacity changes reject zero, re-check provider capacity and duration ranges,
  validate before payout, and re-base the remaining service window.
- Provider deletion drains both derived pools after agreements settle.
- Solvency and expiry-liveness invariants report collateral shortfalls and
  overdue agreements.

### Determinism and state validation

- Every CurrentContext cache map commits in sorted key order. This is
  consensus-critical because address commits may allocate auth account numbers
  from a global sequence.
- Consensus-visible Unicode classification, case conversion, and whitespace
  handling use checked-in Unicode 15.0.0 tables. NFC remains pinned by
  `golang.org/x/text` in `go.sum`.
- Message-supplied player ids resolve through `GetExistingPlayer`; allocator
  getters no longer masquerade as existence checks.
- Destroyed structs are rejected throughout their delayed sweep window, and
  destruction is idempotent.
- Brownout capacity calculations clamp at zero rather than underflowing.
- Automated-allocation indices are cleared under the same source id used to
  create them.
- Ante throttle reservations validate authority over caller-supplied targets
  before writing object-global keys. A failed ante-time authorization skips the
  reservation rather than rejecting transactions that establish permission in
  an earlier message.

## Migration order

The order in `CreateUpgradeHandler` is part of the repair:

1. `MigrateProviderPoolAddressIndex` builds the pool allowlist before any
   guild-token balance moves.
2. `MigrateProtectLegacyGuildEscrow` marks existing native-token escrow backing.
3. `MigrateGuildBankFees` initializes nil fee fields to zero.
4. `MigrateGuildNameIndex` rebuilds normalized name keys under pinned Unicode.
5. `MigrateGuildJoinBypassLevels` clamps undeclared policy values to closed.
6. `MigrateGuildCharter` initializes charter params, anchor, and reactor
   eligibility heights.
7. `MigrateStructTypes` writes `canDefend`, then
   `MigrateDefenderCanDefend` removes invalid defender relationships.
8. `MigrateOreClocksToPlanet` moves shared ore clocks and counters to planets.
9. `MigrateRaiderArrived` seeds the raid-pause clock.
10. `MigrateJailedReactorEnergy` gates reactors already jailed or missing.
11. `MigrateInfusionOwnership` re-homes infusions before capacity is recomputed.
12. `MigrateDelegationDistributionState` repairs recoverable destination reward
    state left by raw delegation rekeys.
13. `MigrateAuditDelegatorShares` reports unrecoverable share discrepancies
    without guessing at ownership.
14. `MigrateReconcileReactorInfusions` rebuilds reactor infusions from staking.
15. `MigratePrimaryAddressPermissions` restores the permission ceiling expected
    by primary-address updates.
16. `MigrateFleetQueueLimit` seeds queue counts and returns overflow fleets.
17. `MigrateAgreementCheckpointOverbill` returns one block of over-billed
    revenue to collateral pools.
18. `MigrateExpireOverdueAgreements` settles overdue agreements after that
    collateral repair.
19. `MigrateStructPhantomAggregates` recomputes player and planet aggregates.
20. `MigrateOrphanedAllocationControllers` re-homes phantom controllers after
    all earlier teardown paths have run.
21. `MigrateAutoResizeAllocationIndex` rebuilds the index last from surviving
    allocations.

## Operator expectations

- The release is a coordinated binary upgrade; consensus changes are active as
  soon as the new binary runs, not only inside the migration handler.
- `MigrateAuditDelegatorShares` is intentionally read-only. Any discrepancy it
  reports needs operator review because stored state cannot identify which
  delegator lost shares.
- Infusion reconciliation may reduce phantom grid capacity and trigger the
  normal EndBlock grid cascade.
- Name-index repairs, unknown policy clamps, overdue agreements, provider
  shortfalls, legacy escrow balances, and delegation-share discrepancies log
  prominently because healthy state should make those paths no-ops.
- The migration functions are idempotent where practical and have focused tests
  in `app/upgrades/v0_21_0/upgrades_test.go`.
