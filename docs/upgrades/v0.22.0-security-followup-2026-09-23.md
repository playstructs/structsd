This records the additional review after the September 22 remediation. Changes

## Findings addressed

1. **Failed settlement during substation deletion.** Agreement teardown releases
   its recursion guard on error. A later attempt in the same CurrentContext must
   settle again rather than bypass payment and delete the allocation. GridCascade
   visits each object at most once per call and leaves a requeued object for a
   subsequent pass. Regressions drain the collateral pool, fail settlement twice,
   verify the agreement/allocation/provider load remain intact, refill the pool,
   and verify exactly one consumer payout. The queue regression advances blocks
   and verifies one retry sequence increment per pass. Existing bounded-cascade
   and deletion-budget suites also pass.
2. **Owner capacity allowance contaminated by other caches.** CurrentContext now
   maintains an owner-scoped secondary view of its canonical infusion caches.
   Loads, creation, ownership changes, genesis import and deletion keep that view
   current. Inventory checks count only that owner's raw index rows and new
   uncommitted rows, with no second charge for a row already loaded. Missing-row
   probes and other owners do not consume the allowance. The secondary view is
   not committed separately: the canonical infusion map still commits once in
   sorted order. Live staking eligibility remains freshly evaluated, including
   jail/slash changes within the same context.
3. **Joining a closing entry substation.** Direct membership, invitation/request
   acceptance and rank-purchase admission reject a closing destination. Invitation
   overrides are rechecked too. Rejection preserves membership, rank, existing
   connections and pending proposals; rank-purchase rejection occurs before
   payment. The signed rank-purchase test checks financial/event rollback.
4. **Logged reconciliation failure had no retry.** A non-cancellation failure in
   AfterDelegationModified now schedules the existing bounded reactor repair
   queue. Scheduling starts a fresh snapshot so a previously visited position
   cannot be missed. Failed repairs remain queued; once the injected error is
   removed, repair completes without duplicate capacity credit. Cancellation
   restoration errors continue to abort the transaction. Consensus slash liveness
   and the full staking integration suite still pass. No audit-history subsystem
   or new persistent queue is added.
5. **Formatting.** Applied gofmt to the two files identified by the reviewer:
   `msg_server_allocation_create.go` and `structs_decorator_test.go`. No repository
   format or lint sweep was run.

## Workspace dependency and cache clarification

`third_party/cosmos-sdk` is required build input through the root go.mod local
replacement. Its source, license, provenance, verifier and reviewed patch belong
in Git. The patch supplies both staking slash fixes and the unbonding integration
needed to preserve cancellation efficiency. `third_party/README.md` now documents
all modified/added files and this checkout requirement. It must not be ignored.

Added ignore rules for Python `__pycache__`, `.pyc` and `.pyo` files. Existing rules
already cover build output, chain databases in build/, logs and reference checkouts.
The approximately 21 GB of local build/rehearsal evidence remains on disk.

SDK CacheContext's returned `write()` merges isolated store changes and events
into its parent. Our CurrentContext still deduplicates object reads and commits
objects deterministically. Where combined, CommitAll runs before write. Normal
transactions already have SDK rollback; extra nesting should be reserved for a
specific atomic boundary. A child write does not refresh an outer object cache,
so it must not be followed by commits of stale outer objects.
