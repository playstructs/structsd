## Resource and interface boundaries

The full BaseApp combined workload includes PreBlock, BeginBlock, two signed
transactions, double-sign evidence, EndBlock and Commit. It verifies exact
payments, rollback, burns and refunds while all tested queues drain in 262 blocks.
Separate upgrade diagnostics reach 2,048 owners and 8,192 pending staking entries;
wide-owner/slashing diagnostics cover 1,024 and 4,096 addresses. These tests found
and fixed permission-cleanup amplification and repeated SDK slash work.

These are finite developer-machine diagnostics, not a production throughput
guarantee. The larger encoded migration RPC result is 33.6 MB. No single fixture
simultaneously maximizes validator count, transactions, vesting schedules,
destroyed structs and every queue. That limitation must remain explicit rather
than implying that a measured fixture proves an arbitrary network-size bound.
See the [performance record](v0.22.0-economy-performance.md).

Proto/OpenAPI generation and FILE compatibility against both recorded release
baselines pass; the 80 corresponding interface inputs still match the recorded
proof. The [client reference](v0.22.0-economy-client-reference.md) and
[operator notes](v0.22.0.md) describe the current fields, migration order,
retained-account exception and recovery procedure.
