# v0.22.0 chain-event contract and verification

## Current reactor contract (September 23 replacement)

The [reactor replacement](v0.22.0-reactor-replacement-plan.md) supersedes every
efficiency-ranking, grandfathering, weight, pending-efficiency and activation
reference in the dated evidence below. Those unshipped protobuf fields, queries
and event messages have been removed. Flat 1:1 infusion power retains the existing
commission split. Cancellation follows current backing and cap admission; no
historical efficiency payload is required.

| Message | Meaning |
| --- | --- |
| `EventInfusion` | Replace the canonical infusion, including its asset owner, fuel, power, commission and pending unbonding amount. This is the base position, not the owner's diversity bonus. |
| `EventOwnerReactorDiversity` | Replace the named owner's current `power`, `squaredPower` and `appliedBonus`. `power` sums post-commission reactor contributions, aggregated across the owner's addresses per reactor before squaring. Zero totals clear the portfolio; generators and received allocations do not enter these totals. |
| `EventOwnerReactorDiversityReset` | Clear only the diversity-summary projection. Sorted owner summaries follow once on the first block after genesis import, including imports starting above height one. Ordinary upgrades publish their reconstructed rows without this reset. |
| `EventReactorStakeCap` | Replace `active`, `capBps` and `minValidators`. Activation is sticky. The upgrade publishes an initial snapshot; later activation/settings changes publish current values. |
| `EventGrid` | Replace the named grid attribute. Owner primary capacity includes the applied diversity bonus. Bonus reductions can resize automated allocations and queue normal GridCascade. |

All numeric amounts must retain exact integer precision. Portfolio totals are
decimal strings; the applied bonus is bounded by available uint64 grid capacity.
Cache commits coalesce unchanged owner summaries and publish changes in sorted
order. Rolled-back transactions and failed upgrades publish no success events.
These are current-state updates, not an on-chain activity journal.

`owner-reactor-diversity [owner-id]` exposes stored totals/applied bonus separately
from current native-stake `liveBonus`, `usableBonus` and usable primary capacity.
Incomplete address/delegation inventory means the live bonus is unknown (empty
string), not proven zero. `livePortfolioComplete` and `infusionInventoryComplete`
must be checked before interpreting a projection. Reads never credit new capacity;
normal reconciliation does. `reactor-stake-share [reactor-id]` reports admission
inputs/headroom and retains commission-repair revisions independently of diversity.
The commission-revision events and their reset remain in use.

Current implementation and verification limits are recorded in the
[replacement progress document](v0.22.0-reactor-replacement-progress.md).
Older native runs below do not certify this candidate. Indexer code remains
separate user-owned work; this contract documents the chain's output only.

Tombstoned-validator recovery now has a public refund-event check: after vault
migration and full defusion, an actual maturity block emits exactly one
`coin_received` for the vault and one `complete_unbonding` identifying that vault,

credit. Indexers must not treat a nonzero cached `Defusing` value as evidence
that an already delivered `complete_unbonding` refund is still unpaid.
Empty-infusion deletion has its own rotating 128-entry cleanup budget. A zeroed
infusion can remain present until its cleanup turn; its later deletion event
does not represent another asset movement or power reduction.
SDK hold release is another distinct path: `UnbondingCanComplete` can directly
credit a matured vault unbonding without emitting `complete_unbonding`, which
the ordinary staking EndBlock loop emits. Bank credit events remain the balance
signal. Structs retains a bounded retry for matured held entries so a later
release eventually clears `Defusing`, without treating reconciliation as payment.

Permission cleanup for objects deleted in Structs block hooks now runs entirely
through the existing shared 256-unit cleanup budget (queue visits and removed
rows). Object deletion, agreement expiry and monetary settlement still occur
immediately. `EventPermission` and `EventGuildRankPermission` row-removal events
can follow in later blocks; indexers must treat the deleted object as unusable
without waiting for every grant row to disappear. This affects grants on destroyed
objects only. It does not revoke surviving child-object grants after membership,
rank or guild-owner changes. Transaction teardown keeps its bounded first pass.
The combined EndBlock regression checks exact payouts throughout backlog draining.

The live script's rank-purchase event decoder has offline coverage in

emitted in sorted record-key order after the records, indices and queues have
been written. Existing vault entries are included once, not emitted again for
each incoming source, keeping payload size linear in the merged entries.

### Slash-repair eligibility visibility

`QueryReactorStakeShareResponse` carries `slashRevision` (tag 9),
`reconciledSlashRevision` (tag 10), and `commissionRepairPending` (tag 11).
The boolean is true exactly when the revisions differ. It reports the slash-repair
gate on commission admission; false does not establish validator eligibility,
spare capacity, or complete gameplay readiness. Malformed internal revision state
returns an Internal query error instead of a clean default. Revisions are uint64;
clients must preserve their full integer precision.

| Event | Consumer action |
| --- | --- |
| `EventReactorCommissionRevision` | Replace the named reactor's revision pair with `slashRevision` and `reconciledSlashRevision`. Unequal values mean slash repair is pending. |
| `EventReactorCommissionRevisionReset` | Clear the commission-revision map. Subsequent revision events repopulate it; absent rows have the initial `0/0` pair. This resets only revision tracking, not reactor, grid, vault or asset accounting. |

A positive active-economy slash advances the issued revision and publishes the
new pair. Successful repair publishes its reconciled revision only after infusion
and grid commits; it may not certify a newer slash using an older pass. Failed
repair publishes no certificate. Manual restart neither advances the slash
revision nor emits an unchanged pair. Existing infusion/grid events continue to
describe accounting progress while the reactor remains pending.

The complete upgrade handler emits a reset/replacement in the actual upgrade
block after migration and activation, inside their atomic cache. Genesis replay
also publishes a replacement. Since InitChain events are not delivered as block
events and an imported chain can start above height 1, InitGenesis persists a
one-time replay marker. The first resumed block publishes and clears it. At
height 1, the normal full-genesis replay already supplies the replacement; at a
higher height, the marker causes a dedicated replay. Ordinary continuation emits
no repeat reset. Revisions can therefore return to zero after a genesis rebuild:
consume reset and row events in block order, atomically, rather than rejecting a
lower number using a lifetime high-water mark. A reset without rows is meaningful.

Typed payload attributes are JSON encoded. SDK block results may also contain a
plain-text `mode` attribute (`BeginBlock`, for example); exclude that metadata
before parsing the protobuf payload. Deduplicate using committed event identity,
not revision numbers alone across resets. Discarded cached slash or repair work
must not affect the consumer's state.

Real-app tests decode the actual upgrade and first/second restart block outputs,
cover both export height modes, replay a reset over obsolete indexed state, and
check query JSON, failed/repeated repair, event ordering and cache rollback. A
malformed snapshot is validated before its reset is emitted. These tests establish
the producer contract for the covered cases; production payload limits and full
economic acceptance remain chain release gates. Actual GRASS/structs-pg
consumption is separate user-owned work.


### Deferred shutdown accounting

Native departure from the bonded set queues infusion cleanup. Existing infusion/grid events describe the positions actually processed
by each block; they do not advertise that every pending row is already zero.
Live validator eligibility can make a position unusable before its stored power
and downstream grid records change. Positive stored power therefore is not proof
of gameplay readiness. Likewise `commissionRepairPending = false` only describes
the slash revision pair and does not rule out a shutdown or recovery queue.

Actual shutdown blocks in `TestBondedReactorRestoresInBoundedBlocks` emit one
tracked zero-power infusion update per completed position, within the shared

recovery block stream reconstructs the entire infusion and nonzero grid state.
BeginBlock genesis snapshots are distinguished from EndBlock shutdown deltas;
SDK `mode` metadata is excluded when decoding the typed payload.

This establishes stored-accounting event delivery for the tested transitions.
Payments continue by elapsed blocks until ordinary cascade teardown or expiry;
readiness loss does not introduce a separate outage-pricing clock. Updated real
SDK outage cases exercise this confirmed behavior. Freeze the event contract
after chain-side payload and delivery verification; downstream acceptance is
separate user-owned work.

### Generator lifecycle accounting events

The subsequent bounded lifecycle implementation adds `generatorDisabled` to the
existing `Infusion` payload. A disabled position retains fuel and its historical
integer ratio, while power is zero. Use the reported power and disabled flag;
`fuel * ratio` alone no longer describes a disabled generator position. The
