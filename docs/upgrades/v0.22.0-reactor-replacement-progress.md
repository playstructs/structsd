  interface education is the user's chosen response.

## Work completed so far

- Proxy admission now checks that the selected substation accepts connections
  before player creation or membership changes. A new four-case regression covers
  registered/unregistered addresses and default/override stations, unchanged
  membership/index/count on rejection, and reuse of the signed nonce proof once
  the station opens. The default-station cases failed before the fix.
- Reactor repairs now advance the finite main interval past failed positions.
  A deduplicated FIFO retains failures, rotates persistent failures behind other
  pending rows, and shares the existing position budget with the main pass.
  Repeated failed delegation hooks preserve the main interval and queue the
  affected address, including a not-yet-created infusion. A real slash or bonding
  transition still captures a new interval. Certification requires both the
  interval and retries to finish. Each attempt commits its object/SDK caches
  only on success, isolating partial changes and events from neighbouring rows.
- Asset-owner validation now lives in `types/asset_owner.go`. Genesis owner
  resolution, live delegation/unbonding reconstruction, grid installation and
  maturity scheduling now live in `keeper/reactor_infusion_genesis.go`. The
  generic importer rebuilds flat power, including vault and unbonding-only
  positions; live delegations missing from an export are discovered at genesis.
- The unshipped efficiency implementation, stored weights, pending cancellation
  history, snapshot pricing, activation flag, RPC, and efficiency-only events are
  removed from production source and protobuf schemas. Generated Go/API/OpenAPI
  output was regenerated. Flat 1:1 power retains commission splitting, live
  bonded/jailed eligibility, bounded repair, and commission certification/replay.
- Mixed tests now assert flat backing while retaining staking/distribution
  conservation, merged native unbondings, cancellation, vault rotation,
  rollback, pending repair, and both export-height restart cases. Generator
  teardown tests use the bounded worker rather than assuming immediate cleanup.
- SDK `delegation.go` and `msg_server.go` now match upstream v0.53.8 and the
  efficiency-only unbonding context file is removed. Independent `slash.go` and
  `slash_context.go` changes remain. Patch, provenance and dependency checks were
  updated together. Verification covers 2,137 files; SDK staking keeper tests pass.
- `test_chain.sh`'s defuse/cancel phase and its Python verifier now check flat
  backing. Upgrade backing and infusion/grid event replay verifiers no longer
  require retired efficiency fields/events. The upgrade runner now independently
  verifies cap activation events, threshold/sticky state, and exported parameters;
  export/restart verification checks preservation. Diversity checks remain pending.
- The stake cap is enforced through real staking before/after hooks, with a
  transaction-scoped transient snapshot consumed after each operation. Checks
  use current validator tokens and actual bonded-pool balances, with the target's
  own tokens included when unbonded. Arbitrary-precision comparisons avoid SDK
  integer multiplication overflow. Existing over-cap stake may leave or be
  slashed; new stake, including canceled unbondings, must satisfy the cap.
- Cap activation is evaluated against the installed bonded set at genesis,
  upgrade and EndBlock. It remains active after validator-count loss and both
  normal-height and zero-height export/restart. Genesis and migration install
  the new parameter defaults before dependent hooks run. Governance can update
  cap settings; changing diversity pricing through `MsgUpdateParams` is rejected.
- The replacement `reactor-stake-share` query exposes current share inputs,
  separately priced external-deposit/bonded-redelegation headroom, and retained
  commission-repair certification. Typed cap events expose activation/settings.
  Protobuf, CLI and OpenAPI were regenerated together.
- Cap regressions cover native and vault deposits, exact rounding boundaries,
  all four redelegation pool combinations, new validators, authz, cancellation,
  multi-migration guild join rollback, and production nine/ten-validator bootstrap.
  A signed two-signer batch proves an earlier successful message rolls back when
  the later message exceeds the cap; a valid next-block retry succeeds. This
  exposed and fixed generic ABCI error reporting: cap refusals now preserve their
  dedicated code and diagnostic values through BaseApp wrapping.
- ICA tests invoke the real host packet receiver and message router under both
  wildcard and native-message allow-lists, in protobuf and proto3 JSON. Failed
  multi-message packets roll back balances, staking, cached state and events;
  a valid packet in the same context then succeeds. They seed established
  channel/account state and do not test handshake proofs or relayer operation.
  They establish cap enforcement, not the separate Structs-through-ICA policy.
- Historical slashing tests follow pending redelegations into an already
  over-cap destination, with both healthy and deliberately unrepairable infusion
  rows. Native slashing succeeds and staking/distribution invariants hold.
- The diversity arithmetic helper and tests are implemented with arbitrary-
  precision intermediates and one final division. Tests cover parameterized
  curves, exact rational reference comparisons, invalid totals, portfolio
  splitting, and the accepted 2,859-to-2,855 power reduction from a deposit.

  event are generated. `CurrentContext` now has keyed position and summary
  caches, sorted commit coverage, and refresh-before-capacity-read/commit support.
  Updates aggregate addresses before squaring, exclude generator power from the
  formula, remove empty records, and coalesce unchanged events. Zero transitions
  still emit. The combined base/bonus mutation removes the old bonus before
  changing base capacity, then clips the new bonus to available uint64 room.
- Cache tests prove the accepted concentrated-deposit reduction queues cascade
  and resizes an automated allocation. Overflow tests preserve base power while
  clipped bonus disappears and returns. Updating one portfolio uses 15,152 gas
  with either 10 or 2,000 unrelated owners; it does not scan their records.
- Atomic reconstruction and an independent accounting checker are implemented.
  Reconstruction derives grouped post-commission shares from canonical infusions,
  replaces prior derived state, applies the bonus once, and clears vanished
  portfolios. Tests cover idempotence, commission/aggregation, failure rollback,
  zero events, and cascade on a reduced reconstructed bonus. The checker is now
  registered as `reactor-diversity-consistency` after reconstruction is ready.
- The guild-sale treasury policy is documented as accepted existing behavior.
