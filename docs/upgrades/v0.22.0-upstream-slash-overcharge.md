# Upstream SDK redelegation slash overcharge

Decision: September 28, 2026. Structs uses unmodified Cosmos SDK v0.53.8 and
accepts this known upstream limitation for v0.22.0. The local correction and
`third_party` SDK snapshot are removed. No report has been submitted by this task.

## Issue to report

`x/staking/keeper/slash.go`, `SlashRedelegation`, first collects an eligible
redelegation penalty from pending withdrawals at the destination validator and
subtracts that payment from `slashAmount`. If a positive remainder exists, it
then burns active shares using `slashFactor * entry.SharesDst`, without capping
that burn to the remaining penalty. Partial pending payment can therefore make
the total burned exceed the entry's nominal penalty.

Reproduction with no prior destination slash and a one-to-one share price:

1. Delegate 2,000,000 base units to validator A.
2. Redelegate 1,000,000 to validator B.
3. Undelegate 30,000 from B, leaving the withdrawal pending and slashable.
4. Apply a 10% slash to the eligible redelegation for A's earlier infraction.

Expected penalty for the moved stake: 100,000 base units. Pending withdrawals
pay 30,000, leaving at most 70,000 to collect from active stake.

Observed on upstream v0.53.8: 30,000 pending plus 100,000 active are burned,
for a total of **130,000**, while `SlashRedelegation` returns the nominal
**100,000**. The extra 30,000 is destroyed, not paid to another account.

No vault migration is needed to reproduce this. The test uses native staking
messages and keepers without invoking an upgrade migration. It also exercises
the complete source-validator slash path, not just direct `SlashRedelegation`.

## Executable reproduction

From the repository root:

```sh
STRUCTS_REPRO_SDK_SLASH_OVERCHARGE=1 go test ./app \
  -run 'TestReproduceSDKRedelegationSlashOvercharge/source_infraction=false/pending=30000/prior_destination_slash=false$' \
  -count=1 -v
```

This deliberately fails on the expected upper bound with:

```text
SDK overcharge: pending=30000 total burn=130000 active limit=70000 actual active burn=100000
```

Use `source_infraction=true` to exercise the full source-validator slash entry
point, or select only `TestReproduceSDKRedelegationSlashOvercharge` to run the
whole matrix. The matrix covers zero, one-unit, partial, exact and excess pending
coverage, with and without a prior destination slash.

The ordinary test suite runs the same matrix in
`TestUpstreamRedelegationSlashPendingPaymentAccounting`, checking the pinned
upstream behavior, remaining balances, shares and staking/distribution invariants.
Only the explicitly failing reproduction requires the environment variable.
Passing the ordinary suite does **not** mean the overcharge is fixed.

## Adoption and build policy

The root module has no SDK replacement. Builds use the upstream v0.53.8 module
and its Go checksums. Dependency tests retain the security version floors and
reject SDK replacements. The rehearsal builder records module-file hashes and
linked dependency versions; it no longer uses local SDK provenance files.

An eventual upstream correction needs review of remaining-penalty limits,
destination share prices, rounding and final-share behavior. On adoption, update
the accounting expectation and make the currently failing cap assertion part of
the default passing suite. Any changed slash burn must be deployed consistently
across validators as part of a coordinated upgrade.

## Validation

The isolated reproduction was rerun against upstream v0.53.8 and failed with
the exact 130,000/100,000 discrepancy above, both through direct redelegation
slashing and the full source-validator slash entry point. `go mod verify` passed, and
`go list -m github.com/cosmos/cosmos-sdk` reports v0.53.8 without a replacement.
The rehearsal build script passes shell syntax checking.

A fresh `go build -mod=readonly` binary succeeds. Its `go version -m` output
confirms upstream SDK v0.53.8 with checksum
`h1:rKQIgqifo3Izv/JQLpPIjReOJ7jK+Qh8Rt8GIttDADw=` and no SDK replacement.
The SDK staking keeper suite passes separately.

`go test ./...` passes against the unmodified SDK, including native evidence,
retained-staking upgrades, events and restart tests. A fresh native-node
upgrade/reopen rehearsal remains outstanding for this candidate.
