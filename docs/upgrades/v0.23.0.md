# v0.23.0 development

Development began November 9, 2026 on the existing `119b` branch. All structsd
release work stays on that branch; do not create additional branches or merge
this work to master. No upgrade height, release tag, publication, or deployment
is selected by this setup.

## Upgrade setup

The on-chain plan name is **`v0.23.0`**. Following the previous releases,
`app/upgrades/v0_23_0/constants.go` defines the name and `upgrades.go` supplies
`CreateUpgradeHandler` and `NewUpgrade`. `app/app.go` registers the handler and
uses the existing upgrade-info/store-loader mechanism.

The initial handler only calls `ModuleManager.RunMigrations`. There are no new
store keys or Structs state migrations, and it does not replay the v0.22.0 economy
conversion. Add future v0.23.0 migrations to this handler as development proceeds.
Historical handlers and upgrade documentation remain intact.

Build a development binary with `make build VERSION=v0.23.0`. Without an override,
the Makefile retains its existing Git-derived development version. A release tag
triggers publishing, so do not create one as part of development setup.

## Dependency housekeeping

Inspection of both the starting `119b` checkout (`fe8d9898`) and local tag
`v0.22.0` found the requested upgrades already present. No dependency bump is
needed in this initial v0.23.0 change:

| Module | Retained version | Protection |
| --- | --- | --- |
| CometBFT | v0.38.26 | Includes the v0.38.25 mempool gossip filter and recheck race fixes. |
| Cosmos SDK | v0.53.8 | Transaction decode/multisig hardening, SEC1 public-key validation, and distribution fixes. |
| ibc-go/v10 | v10.7.0 | Includes the v10.1.0 acknowledgement round-trip fix for ASA-2025-004. |
| IAVL | v1.2.8 | Explicit requirement preserves the fast-node cache race fix independently of the SDK's lower requirement. |

`app/arch_deps_test.go` retains floors of CometBFT v0.38.25, Cosmos SDK v0.53.8,
IBC v10.1.0, and IAVL v1.2.7. The `golang.org/x/text` replacement remains at
v0.28.0 to preserve the reviewed normalization behavior. No toolchain, dependency
replacement, or module consensus version is changed by this scaffold.

The SDK SEC1 check and IBC acknowledgement check change accepted inputs. A chain
still running a binary without those fixes needs a coordinated upgrade; these
must not be introduced there by a rolling binary replacement. For the inspected
v0.22.0 source baseline, those fixes are already included. Confirm the actual
running binary's build dependencies when preparing the eventual rollout.

`app/ibc.go` already calls `SetRouterV2(ibcapi.NewRouter())` next to `SetRouter`.
No IBC v2 applications are registered. Unlike the legacy router, the upstream
v10.7.0 v2 router has no `Seal` method, and `SetRouterV2` only assigns it. An
unknown port takes the explicit `no route for <port>` panic path, recovered by
BaseApp during transaction execution, rather than dereferencing a nil router.
Do not describe this as a sealed router or an ordinary returned error.

## Validation

The new in-process app regression applies the registered v0.23.0 handler through
x/upgrade, checks completion and the module version map, and compares exported
Structs state before and after. A second regression checks the initialized empty
IBC v2 router and its explicit missing-route behavior.

Validation completed November 9, 2026:

- Focused upgrade, router, and dependency-floor tests passed.
- Full `make test` passed after correcting the new test's fixture version map
  and SDK header height.
- `make build VERSION=v0.23.0` passed; `build/structsd version` reports v0.23.0.
- Binary build metadata confirms CometBFT v0.38.26, SDK v0.53.8, IBC v10.7.0,
  IAVL v1.2.8, and the retained x/text v0.28.0 replacement.
- `git diff --check` passed; go.mod and go.sum are unchanged.

A real v0.22.0-to-v0.23.0 halt/restart rehearsal is
still a release gate once the release scope and upgrade height are finalized;
the in-process test is not a substitute for that rehearsal.
