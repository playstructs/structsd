## Additional review follow-up

The latest review found two gaps in the earlier fixes: the per-player admission
counter still charged downstream CheckTx failures, and entry-rank changes still
accepted rank-derived Update. Both are now corrected and covered by regressions.
Both address and player admission counters preflight caps and increment only after
successful downstream ante processing. Multi-player admission cannot partially
consume another player's quota.

Kicks preserve independent direct grants. Guild-source allocations default to
guild control; assigning another controller requires source administration, and
source administrators can reclaim static/automated allocations. Large substation
deletions close admission and drain indexed connections through bounded
GridCascade work. The unused recursive graph checker is removed.

Cancellation restoration errors now propagate through the outer staking hook and
abort the cancellation transaction. Real SDK native and Structs cancellation tests
inject an insufficient pending efficiency basis and verify rollback. The separate
consensus-slashing liveness regression continues to pass.

## Confirmed policies

- Allocation contributions remain open. Readiness and admission use local grid
  accounting; bounded GridCascade propagates shortages. The unused recursive
  supply checker has been removed.
- Transferring a guild clears every direct permission of its previous owner on
  that guild. Independent grants on child objects remain until revoked.
- Buying or holding a rank supplies configured operational rights. Promotions,
  demotions, permission administration and ownership transfers require explicit
  administrative authority, with the signing key's permissions still a ceiling.
- Cancellation restores the pending stake's prior efficiency. Metadata exists
  only for live native unbonding entries and is pruned when they finish. This does
  not reintroduce historical billing or service audit logs.
- Existing provider/agreement elapsed-block payments and GridCascade settlement
  continue. Indexer changes and downstream testing remain the user's work.

## Review findings and resolutions

| Finding | Resolution and evidence |
| --- | --- |
| Predictable vault pre-created as a native vesting account halts migration | The migration accepts all four supported native vesting account types at the destination and preserves their locks alongside relocated vesting obligations. Real SDK tests create continuous, delayed, periodic and permanent locked destinations, each with ordinary and vesting sources. Re-creation after provisioning is rejected by native SDK account-existence checks. This is tolerance of future-address prefunding, not a claim that arbitrary future hashed vault addresses can be globally identified and banned. |
| Dust freezes the next guild ID | Paid founding checks guild-token supply, absorbs existing collateral and does not reject a positive ualpha balance. Keeper and signed transaction regressions cover dust. |
| Open contributions exhaust recursive supply proof and disable victims | Player secondary readiness, substation headroom and allocation admission no longer require the recursive proof. Local arithmetic guards brownouts; GridCascade sheds load and settles agreements normally. A regression creates/connects 2,050 donor allocations through handlers, verifies the victim remains online and checks constant readiness gas. A 10,000-station graph also avoids recursive admission cost. The unused graph checker and its diagnostic-only tests have been removed; actual gas/readiness regressions remain. The existing disconnect path also accepts authority on the destination substation; it does not require the recipient to control the donor's allocation. The native fixture exercises that path. |
| Missing infusion row earns grandfathered efficiency | Delegation transfer preserves the lookup's found flag. An absent source is priced as new stake rather than a pre-upgrade position. Real staking/distribution tests cover both an empty destination and an existing destination. |
| Seller retains treasury permission | Ownership transfer clears the complete outgoing-owner guild row. `PermGuildAll` includes asset operations, source allocation and allocation connection. Migration removes newly effective economic bits from pre-existing guild and guild-rank grants so previously inert bits do not become treasury authority. Current ownership supplies the owner's capabilities. |
| Purchased rank becomes permanent administration or free promotion | Rank-derived Admin is excluded from permission resolution. Permission grant/set/revoke, rank permission configuration, rank assignment and guild transfer require explicit administration. Ante checks require the fixed Admin bit. Regressions prove operational token authority works while self-grants, ownership seizure, free promotions and paid-member demotions fail; explicit direct administrators retain these operations. |
| Full undelegate/cancel reprices stake | Infusions retain fuel and weight by live native unbonding entry ID. Cancellation restores the corresponding prior rate; partial cancellation, merged entries, multiple entry rates, maturity and restart are covered against real SDK hooks. Missing metadata never creates a grandfathered rate. Existing pending stake is explicitly grandfathered during migration. |
| Offset bypasses query work bound | Excessive offsets return InvalidArgument; callers continue with pagination keys. Limit capping and count suppression remain. Query and architecture tests cover the error path. |
| Pending repair can abort consensus slashing | The SDK's pair-bound consensus slash context bypasses auxiliary user-delegation preparation. The bounded repair queue remains responsible for repair. A real SDK test proves corrupt pending efficiency blocks a user operation but does not abort SlashRedelegation. |
| Corrupt state can abort upgrade | Financial consistency checks remain strict rather than silently discarding obligations. The actual scheduled upgrade passed on a copied live testnet database; details and the pre-existing malformed bank row are below. This is not proof for mainnet state. |
| Paid founding allows jailed primary reactor | Founding requires an existing, unjailed validator, without ownership or control requirements. Signed and keeper fixtures exercise it. This check is at founding; a guild's validator can become jailed later. Existing membership rules that count already-owned stake are unchanged. |
| Third-party owner/controller assignment | Source authorization and existing-recipient checks remain. A player recipient can receive an allocation, substation or provider without signing; this does not debit their wallet or create personal debt. Provider obligations are funded from consumer escrow, and provider creation requires source-substation authority. Guild-owned provider/substation creation additionally checks guild authority. No new recipient-consent protocol is introduced. Gifted assets should not be presented by clients as proof of recipient endorsement. |
| Failed ante consumes CheckTx quota | Both node-local address and player counters preflight all participants and count only after downstream ante succeeds. Eighty rejected delegated charge transactions leave primary-key admission available; failed multi-player admission consumes nobody else's quota. |
| Zero-height export strands earned provider penalty | Export settlement releases the served-span provider penalty before resetting the agreement clock. Exact-value and repeat-rebase tests verify payment once and preserved consumer collateral. |
| Stale binary-only / charter documentation | Upgrade constants and repository guidance describe vault/staking migration and single paid founding. The plan, client reference and event contract now record the revised permission and cancellation rules. |

Historical independent direct grants are not reconstructed by provenance or
recursively revoked. The targeted legacy economic-bit migration and outgoing
owner's guild-row cleanup are explicit exceptions, not a general grant history.

## SDK integration

The existing local Cosmos SDK v0.53.8 snapshot gains a narrowly scoped optional
unbonding observer and a cancellation context marker. The observer runs after
native entry/queue persistence, including same-block withdrawals merged into an
existing entry (which do not fire the standard new-entry hook). Dispatch handles
multi-hooks and their DI wrapper. Structs records prior efficiency through its
CurrentContext and transient pre-operation basis, then prunes completed entries.

The existing SDK slash-work patch, file inventory, provenance hashes and
architecture allowlist include these changes. `third_party/verify_cosmos_sdk.py`
verifies all 2,138 snapshot files. The staking and distribution suites pass against
that snapshot. Generated infusion wire types and Swagger were regenerated from
`proto/structs/structs/infusion.proto`.

## Actual testnet rehearsal

A local v0.21.0 binary was built from the live node's reported commit
`48686a95a80f4df983a03a593bc717cc5d6e0898`. Public state sync was used because the
operator's advertised snapshot download returned 404. A newly initialized local
node followed `structstestnet-111`, was stopped and exported at committed height
**2,740,355** (`initial_height=2740356`). No transactions were submitted to the
public network and no existing validator keys were used.

Sources: [operator state-sync instructions](https://moonbridge.org/testnet/structs/statesync/),
[public RPC](https://structs-testnet-rpc.moonbridge.org) and
[public API](https://structs-testnet-api.moonbridge.org).

The opt-in `app/testnet_upgrade_rehearsal_test.go` copies the stopped node's
application database into a temporary private home. It loads those actual stores,
schedules v0.22.0 at **2,740,356**, executes FinalizeBlock/Commit, advances two more
blocks, closes/reopens the database and commits **2,740,359**. It does not first
rewrite legacy state through new-version genesis import. The run passed in about
5.4 seconds, retaining all **3,694 players**. Vault ownership, reactor efficiency,
provider solvency, expiry liveness and native staking/distribution invariants pass.

Exact export comparisons show:

- No delegation-share or complete pending-entry differences from expected vault
  relocation, including the retained validator self-stake exception.
- **658** bank debit/credit events reproduce all valid-address balances and vault
  migration routing with no differences.
- **3,699** unique vault association events match every exported vault owner,
  address and newly created auth account number.
- **113** infusion writes, **24** infusion deletions and **199** grid events replay
  complete infusion/grid state exactly. Activation, efficiency snapshot,
  allocation state and independently checked reactor backing also match. The
  verifier supplies only new protobuf defaults for unchanged legacy generators;
  non-default values still require events.
- The source already contains **90,000,000 ualpha at the empty bank address**. The
  upgrade leaves that malformed row exactly unchanged. The strict bank verifier
  rejects it, as intended. A separate evidence script asserts its exact before/
  after equality and absence from movement events, then runs the unchanged strict
  verifier on all other rows. Original exports are untouched. This legacy anomaly
  is not repaired by allocating its funds to an invented owner.

This is testnet migration and cold-restart evidence. It does not certify mainnet,
validator quorum/network behavior, long-term throughput or a genesis re-import of
that malformed legacy row. Synthetic real-SDK tests separately cover hostile
vesting destinations and financial states absent from this testnet inventory.
